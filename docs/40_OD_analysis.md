# 40 OD分析

親ランチャーの「40 OD分析」、または `bat/40_UI_od_analysis.bat` から起動します。
様式1-3OD／トリップODをトグルで切り替え、ODリスト、ODマトリクス、ODヒートマップ、ゾーン別発生・集中マップを一つの画面で扱います。

## 2つのOD方式

| 方式 | O・Dの定義 | 必要な入力 |
|---|---|---|
| 様式1-3OD | 様式1-3に記録された元トリップの起終点 | スクリーニングCSV＋様式1-3 ZIP |
| トリップOD | 入力CSV内の各トリップの最初行・最終行の座標 | スクリーニングCSVのみ |

左上の2分割トグルで切り替えます。読み込んだデータ・集計結果・対象日設定は方式別に保持します。トグルだけで方式の異なる座標を混ぜたり置き換えたりはしません。

## 操作

1. プロジェクトを選びます。親ランチャーと同じ共通設定を使用します。
2. OD方式を選び、第1・第1.5・第2スクリーニング済みCSVのフォルダを指定します。様式1-3ODの場合はZIPフォルダも指定し、選択方式の「リストを作成」を押します。既存リストがある場合は、右隣の「既存のODリストを読み込む」を使用します。作成と読み込みはどちらか一方で進めます。下位フォルダも検索します。
3. ODリストの作成または読み込みが完了すると「02 対象日・ゾーニング」と集計ボタンが有効になります。開始日・終了日・曜日を確認します。起動時の日付は空欄です。スクリーニングフォルダを指定すると、CSV内の最初・最後の運行日を自動設定します。既存ODリストを読み込んだ場合もリストの期間を設定します。「対象日を個別に選択」で欠損日などを除外できます。
4. 12で作成したCSVをプロジェクトの `12_ゾーニングデータ` に置き、「集計してマップを表示」を押します。
5. タブでOD表、起終点ヒートマップ、ゾーン別発生・集中マップを切り替えます。地図はドラッグ・ホイールで移動・拡大できます。別方式の結果も欲しい場合はトグルを切り替えて集計します。一度集計した結果はトグルで再表示できます。
6. 配色などを調整し「JPEG画像を保存」を押します。「出力フォルダを開く」で結果を確認できます。

## 集計の定義

- キーは **運行日＋運行ID＋トリップ番号**。別日の同一ID・番号を混同しません。IDの先頭ゼロを保持します。
- **様式1-3OD**では、同じ元トリップが複数CSVや第1.5の複数サブトリップに含まれていても1件です。第1.5を入力にしても様式1-3の元トリップの座標を使います。
- **トリップOD**では、CSV内で運行日・ID・番号が連続する区間ごとに最初行をO、最終行をDとします。第1スクリーニングの1ファイルに複数トリップがあっても分けて出力します。並べ替えはせず、入力の行順を使います。
- 第1.5の別々のサブトリップは、同じ元トリップ番号でもそれぞれの切り出し区間の起終点を保持します。入力行の内容が完全に一致するコピーは重複除去します。1行のみのトリップはO=Dです。
- 最初行・最終行の座標が不正な場合、途中の有効点で置き換えません。`INVALID_COORDINATES`としてODリストに残し、集計時に除外します。経度・緯度は様式1-2のO列・P列を使用します。
- 様式1-3はZIP内の `data.csv` を優先します。なければCSVメンバーを走査します。ZIP名に8桁の運行日がある場合は対象運行日のZIPに絞ります。日付のない名前は全件照合します。
- ODリストのstatusは `OK`、`MISSING_OD`（照合なし）、`CONFLICT`（同一キーの様式1-3座標が競合）です。座標が欠損・非数値・範囲外の行は集計時に除外します。
- OD表と両マップは、同じ対象日・status・座標検証を通ったトリップを使い、ゲート端点を別集計します。統合OD表は4区分すべて、地図の通常分布は非ゲート端点を表示します。
- **日平均＝採用トリップ数÷UIで選んだ対象日数**。ゼロ件の日も分母に入ります。欠損日をゼロ交通として扱わないよう、個別選択で除外してください。
- 日平均の単位は「トリップ/日」。プローブサンプルの集計であり、全車両交通量への拡大推計は行いません。
- ポリゴン境界を含めます。異なるゾーン名に重複する点は「【ゾーン重複】」、どのゾーンにも入らない点は「【区域外】」としてOD表に残します。固定都市の東西南北分類は行いません。
- 全ゾーンをOD表に表示します。0件のゾーンも省略しません。同名の複数ポリゴンは同一ゾーンとして集計します。
- 既存リストは同じ方式のCSVを複数読込できます。方式を混在させると停止して通知します。方式列のない旧ODリストは様式1-3ODとして扱います。トリップODには`od_method=trip`と`trip_instance`（区間識別子）が必要です。

## 地図とJPEG

画面は最大化して起動します。数値欄は上下矢印と直接入力で変更できます。

**ODヒートマップ**は起点／終点、配色、不透明度、上限/日、半径、ぼかし、表示倍率を調整できます。近接点の影響を重ねた相対的な密度表示です。色は絶対交通量を表しません。

起点／終点と配色は横並びのボタンで選びます。「透明→青→赤」はゼロを透明、低い値を青系、高い値を赤系で表示します。ゾーン・ゲートにも同じ配色を適用します。ヒートマップのゼロ部分は背景地図をそのまま表示します。数値設定とラベル表示の設定は1行にまとめています。スクリーニングフォルダの参照ダイアログは、選択中のプロジェクトフォルダから開きます。

**ゾーン別発生・集中マップ**は各ゾーンの発生／集中トリップ数を日平均にして塗り分けます。配色、不透明度、上限/日、対数配色、ラベル表示を変更できます。区域外・重複は地図上のポリゴンには加算せず、OD表に別掲します。

- `上限/日=自動` は表示対象ごとに自動設定します。OとDを同じ色尺度で比較したい場合は同じ上限を手入力してください。
- JPEGは**画面内の地図領域のサイズ**で保存します。大きい画像が必要ならウィンドウを広げてください。地図・凡例・期間・出典表記を含みます。背景タイルが表示されてから保存してください。
- 起終点は `【様式1-3OD】ODheatmap(1).jpg` または `【トリップOD】ODheatmap(1).jpg`、ゾーン別は `【方式名】ODzoneheatmap(1).jpg`です。方式ごとに自動連番を付け、既存ファイルは上書きしません。地図の凡例にも方式名を表示します。
- 同名のJSONに描画係数・対象日・画面サイズを記録します。HTMLは集計時の初期表示、JPEGは保存時の表示です。
- Leafletと密度描画を同梱し、Playwrightや追加ブラウザのインストールは不要です。背景は保存済み地理院タイルを優先し、なければオンラインで取得します。両方なければ白地図になります。

## ゲートと4種類の交通

第1.5のトリップOD（および第1.5由来の第2スクリーニング）は、`15_trip_index.csv` の端点判定を使います。ゲートに近いだけの起終点をゲートへ変換することはありません。

| 交通区分 | 起点 → 終点 |
|---|---|
| 内々交通 | ゾーン → ゾーン |
| 内外交通 | ゾーン → ゲート |
| 外内交通 | ゲート → ゾーン |
| 外外交通 | ゲート → ゲート |

- UIとExcelのOD表は、4区分を一つのマトリクスに統合します。行がO（起点）、列がD（終点）です。ゾーンの後にゲートを並べ、0件のゾーン・ゲートも表示します。区域外・ゾーン重複は非ゲート端点の別枠です。
- UIの列見出しは90度回転して幅を抑えます。長い名称は省略表示し、マウスを重ねると全文を確認できます。列幅はドラッグで変更できます。背景色はセルの数値に比例したグラデーションで、合計は別色です。Excelも回転見出し・条件付き書式・行列見出しの固定を設定します。
- ヒートマップ・ゾーン別発生集中には**非ゲート側の端点**を加算します。例えば内外交通はゾーン側の起点を発生に加算し、ゲート側の終点をゲート集中に加算します。ゲート端点はゾーンの値や密度に含めません。
- ゲートは保存されたゲート位置に円を表示し、円内の色で日平均の発生／集中を表します。「ゲート名・日平均を表示」でラベルをON/OFFできます。ゲートの自動上限は通常分布と別に算出し、凡例に表示します。上限を手入力すると両方に適用します。
- 第1.5入力では、スクリーニング時の正式区域を紫の実線、分析区域を青緑の破線で表示します。元の `14_エリアデータ` が必要です。変更された区域で誤表示しないようハッシュ値を照合します。
- 様式1-3ODは元の実起終点なので、切り出し区間のゲート判定を引き継ぎません。第1.5入力の区域線は表示します。
- ODリスト作成時に、端点種別・ゲート番号をCSV、ゲート位置と区域を同名の `.context.json` に保存します。以後は元入力がなくても表示できます。コピーするときはCSVとこのJSONを一緒に移動してください。今回の機能以前に作成したトリップODリストは、元のスクリーニングフォルダから作り直してください。

## 出力

**1回の集計につき `プロジェクト/40_OD分析/【方式名】日時/` を新規作成**します。Excel、地図HTML、集計条件JSON、手動保存するJPEGを同じフォルダに保存します。「出力フォルダを開く」は表示中の集計フォルダを開きます。再集計しても前の結果を上書きしません。

```text
40_OD分析/
  ODリスト/作成日時/
    【トリップOD】od_list.csv
    【トリップOD】od_list.context.json
  【トリップOD】20260917_093000_123456/
    【トリップOD】OD集計.xlsx
    【トリップOD】analysis.json
    【トリップOD】sources.json
    【トリップOD】heatmap.html
    【トリップOD】zones.html
    【トリップOD】ODheatmap(1).jpg
    【トリップOD】ODheatmap(1).json
```

集計表は **`【方式名】OD集計.xlsx` 一冊**にまとめ、集計表のCSVは追加出力しません。

| シート | 内容 |
|---|---|
| 集計条件 | ODの由来（様式1-3／トリップOD）、プロジェクト・スクリーニングフォルダのフルパス、対象日数、採用・除外件数、O/Dと集計の定義 |
| 統合OD表（全期間） | ゾーンとゲートを含む全期間の完全なODマトリクス、行列合計 |
| 統合OD表（日平均） | 同じマトリクスを対象日数で割った日平均 |
| 交通区分別集計 | 内々・内外・外内・外外の合計と日平均 |
| ゾーン別発生集中 | 非ゲート端点の発生・集中 |
| ゲート別発生集中 | ゲート端点の発生・集中 |
| ゲートOD明細 | ゲートを含むODの交通区分・起終点別集計 |
| 対象日 | 分母に使用した運行日の一覧 |

再利用するODリストは `ODリスト/作成日時/` にCSVと `.context.json` の組で保存します。方式を切り替えて作成すると、作成ごとの別フォルダに保存します。既存の出力ファイルは移動・削除しません。新しい構成は次回の作成・集計から適用します。

処理中も画面は応答し、「中止」で中断できます。実行中に画面を閉じるとまず中止を要求します。処理が止まってから閉じてください。

集計条件シートの項目・内容は上下中央揃えです。旧ODリストに元スクリーニングのフルパスが記録されていない場合は「フルパス未記録」と表示します。新しくリストを作成すると、フルパスが保存され、既存リストとして読み込む場合も引き継ぎます。
