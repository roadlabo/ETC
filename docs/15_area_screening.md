# 15 エリア第1.5スクリーニング 操作説明

## 目的

第1スクリーニングで抽出した完全トリップCSVから、指定した分析区域を通行した部分だけを切り出します。区域境界をまたぐ連続2点間では、線分と境界の交点を人工点として作成し、その点をエリア内サブトリップの起点または終点にします。

出力する件数は **ETC2.0観測トリップ数** です。サンプルデータから得られた観測件数であり、道路上の実交通量そのものではありません。

## 第1、第1.5、第2スクリーニングの関係

- 第1スクリーニング: 対象2次メッシュに関係する完全トリップを、運行IDごとのCSVに整理します。
- 第1.5スクリーニング: 第1出力から、分析区域の内側だけをサブトリップとして切り出します。
- 第2スクリーニング: ルートや交差点など、より具体的な条件でトリップを抽出します。

第1.5スクリーニングは、SUMO用ODやゲート間ODを作る前の基礎データ作成に使います。

## 正式区域と分析区域

- 正式区域: 政策・計画・分析上の正式な対象区域です。
- 分析区域: 外周道路を通る車両も確認するため、正式区域の外側に設ける解析用区域です。

分析区域は、正式区域から標準30m外側へ広げて作成します。30mは初期値で、エリア設定画面で変更できます。バッファ生成は緯度経度へ直接数値を足すのではなく、Web Mercatorのメートル座標へ投影してから行います。生成後は地図上で手作業修正できます。

## エリア・ゲート設定

起動:

```bat
bat\15_area_gate_builder.bat
```

操作:

1. `正式区域を編集` を選び、地図をクリックして正式区域のポリゴンを作成します。
2. 必要に応じて頂点をドラッグして修正します。
3. `バッファ` に距離を入力し、`正式区域から分析区域生成` を押します。
4. `分析区域を編集` を選び、外周道路が入るように頂点を調整します。
5. `点ゲートを追加` または `線ゲートを追加` で、分析区域へ接続する道路ごとのゲートを登録します。
6. ゲートID、名称、備考を入力します。ゲートIDの重複は不可です。
7. `妥当性確認` で自己交差などを確認します。
8. `GeoJSON保存` で保存します。

ゲートは交差点内ではなく、できるだけ交差点から少し離れた単路部に置いてください。線ゲートは道路を横切る短い線として設定すると、境界交点との対応を確認しやすくなります。

## GeoJSON構造

1つのFeatureCollectionに次のFeatureを保存します。

- `properties.area15_role = official_area`: 正式区域のPolygon
- `properties.area15_role = analysis_area`: 分析区域のPolygon
- `properties.area15_role = gate`: ゲートのPointまたはLineString
- `properties.area15_role = old_izumo_kaido`: 旧出雲街道のLineString、任意

ゲートFeatureには、`gate_id`、`name`、`note` を持たせます。

## 第1.5スクリーニングUI

起動:

```bat
bat\15_UI_area_screening.bat
```

画面で指定するもの:

- 第1スクリーニングCSVまたはフォルダ
- エリア・ゲート設定GeoJSON
- 出力フォルダ
- サブフォルダも含めるか
- 境界付近許容距離
- 短距離サブトリップ除外しきい値
- 短時間サブトリップ除外しきい値
- 短時間再流入・再流出の統合秒数
- ゲート最大割当距離
- OD時間帯、15分・30分・60分

前回設定はユーザーのホームフォルダに `.etc_area15_screening_ui.json` として保存・復元されます。

## コマンドライン実行

UIを使わずに実行できます。

```bat
runtime\python\python.exe src\15_area_screening.py --input "D:\_EtcData\out(1st)" --area "D:\_EtcData\15_area_gate.geojson" --output "D:\_EtcData\15_result" --recursive --od-interval-minutes 30
```

## 入力データ

第1スクリーニング出力の様式1-2互換CSVを使用します。ヘッダなしを前提とし、既存の第2スクリーニングと同じ列位置を使います。

- 運行日: index 2
- 運行ID: index 3
- GPS時刻: index 6
- トリップ番号: index 8
- 起終点フラグ: index 12
- 経度: index 14
- 緯度: index 15

日時は `YYYYMMDDHHMMSS` を基本とします。日時欠損、座標欠損、点数不足のトリップは除外一覧に記録します。

## 境界交点と時刻補間

連続する2点を線分として扱い、分析区域境界との交点を求めます。交点の緯度・経度は線分上の位置から線形補間します。交点時刻は、前後2点間の線分上の比率で補間します。補間できない属性は推測せず、元行の値を基本に経度・緯度・GPS時刻だけを更新します。

人工点は `is_synthetic_boundary_point=True` とし、`boundary_point_type` に `entry` または `exit` を出力します。

## ゲート判定

境界交点に対してゲートを割り当てます。

- ゲートがLineStringの場合、トリップ線分とゲートラインの交差を優先します。
- 点ゲートまたは交差しない線ゲートは、最大割当距離内の最近傍を採用します。
- 最大割当距離を超える場合は `UNASSIGNED` として出力します。

未割当点は `15_unassigned_gate_points.csv` とログで確認します。

## GPS誤差対策

次の設定を持ちます。

- 境界付近許容距離: 境界に接しただけの区間を内側扱いしないために使います。
- 短距離除外: 極端に短いサブトリップを除外します。
- 短時間除外: 極端に短い滞在を除外します。
- 短時間再流入統合: 短時間で出入りを繰り返す場合に隣接サブトリップを統合します。
- 異常座標、日時欠損、点数不足は除外一覧へ記録します。

## 交通分類

- `gate_to_gate_through`: ゲートから流入し、ゲートから流出した通過交通
- `gate_to_official_internal`: ゲートから流入し、正式区域内で終わる内部交通
- `official_internal_to_gate`: 正式区域内から始まり、ゲートから流出する内部交通
- `official_internal_to_official_internal`: 正式区域内から正式区域内の内々交通
- `perimeter_only`: 分析区域には入るが正式区域には入らない外周道路交通
- `entered_official_area`: 正式区域へ進入したが上記へ整理できない交通
- `unknown`: 判定不能

旧出雲街道はGeoJSONへ `old_izumo_kaido` として保存できる構造にしています。現時点の解析本体では出力構造拡張用に読み込みますが、通過判定の集計列は今後追加する前提です。

## 出力ファイル

- `15_subtrip_points.csv`: サブトリップ軌跡。元の16列を `col_00` から `col_15` とし、追加列を末尾に付けます。
- `15_subtrip_summary.csv`: 1サブトリップ1行の集計表。
- `15_gate_od.csv`: 流入ゲート、流出ゲート、時間帯別のETC2.0観測トリップ数。`ALL` 行も出力します。
- `15_gate_volume.csv`: ゲート別・方向別・時間帯別のETC2.0観測トリップ数。
- `15_excluded_trips.csv`: 除外トリップと理由。
- `15_unassigned_gate_points.csv`: ゲート未割当の境界点。
- `15_multi_entry_trips.csv`: 1トリップで複数回出入りした一覧。
- `15_subtrip_check.geojson`: 地図確認用のサブトリップLineString。
- `15_area_screening_settings.json`: 解析条件の記録。
- `15_area_screening_log_YYYYMMDD_HHMMSS.txt`: 件数と警告のログ。

## SUMO用ODへ利用する際の考え方

`15_gate_od.csv` は、SUMOへ入力するODの基礎表として使えます。ただし、この表はETC2.0観測トリップ数です。実交通量へ変換する場合は、別途拡大係数や検証用交通量との照合が必要です。

## トラブルシューティング

- GeoJSONエラー: `official_area` と `analysis_area` が両方あるか確認してください。
- ゲート未割当が多い: ゲート位置、線ゲートの向き、最大割当距離を確認してください。
- 抽出ゼロ: 分析区域が第1スクリーニング出力の座標範囲と重なっているか確認してください。
- 短い出入りが多い: 境界付近許容距離、短距離除外、短時間除外、短時間再流入統合を調整してください。
- UIが起動しない: `logs\15_UI_area_screening_console.log` を確認してください。

## 具体例

1. `bat\15_area_gate_builder.bat` を起動します。
2. 正式区域をクリックで作成します。
3. バッファ30mで分析区域を生成し、外周道路が含まれるように調整します。
4. 西側、東側、北側、南側など、分析区域へ入る道路にゲートIDを付けます。
5. GeoJSONを `15_area_gate.geojson` として保存します。
6. `bat\15_UI_area_screening.bat` を起動します。
7. 第1スクリーニング出力フォルダ、GeoJSON、出力フォルダを選びます。
8. まずはOD時間帯60分、既定しきい値で解析します。
9. 完了後、`15_unassigned_gate_points.csv` と `15_subtrip_check.geojson` を確認します。
10. 必要に応じてゲート位置や分析区域を修正し、再実行します。
